# Configraft 项目分析笔记 · 学习导航

> **目标读者**：正在准备**校招大厂后端岗位**面试的本人。
> **这套笔记要解决一件事**：让你在面试官面前，能把 Configraft（对标 etcd 的分布式配置中心）**讲得比简历还深一层**——从"我用 braft 做了个配置中心"到"我为什么这么设计、正确性怎么证明、踩过哪些坑、数字怎么来的"。
> **定位**：整合重写 + 定点补缺。吸收仓库内既有高质文档（`../watch.md`、`../m5.md`、`../raft-and-braft.md`、`../安全审查报告.md`、`../性能压测报告.md`），补充缺失的 **bthread 运行模型 / 全链路时序 / 存储 MVCC 深讲 / 集中式 FAQ / 速记卡**。旧文档一律不改，本文档只在文末给延伸链接。

## 一、这套笔记怎么学（三层学习法）

后端项目面试，考察的是**"理解 → 表达 → 应变"**三件事。笔记内容对应用三种用法：

| 层 | 动作 | 对应材料 | 检验标准 |
|---|---|---|---|
| **第 1 层 · 通读理解** | 按 00 → 08 顺序完整读一遍，边读边对照源码 | 全文 | 每个"为什么"你都能复述出理由 |
| **第 2 层 · 合书复述** | 不看笔记，把每章"主干问题"讲给自己/别人听 | 每章末尾的【自查】 | 30 秒能讲清一个特性"是什么/为什么/怎么实现" |
| **第 3 层 · 白板自讲** | 手画时序图 + 背数字 + 应对追问 | `08-面试应试` 第 7.2 白板题 + 7.4 速记卡 | 能连续讲 30 分钟不被问倒 |

> 面试官判断你是不是"真做过"，最有效的一招是**在某个细节上连续追问 3 层**（"为什么"→"那如果…怎么办"→"代码里哪一行"）。所以笔记里所有结论都尽量给到 **源码位置**（形如 `src/raft/raft_node.cpp:166`），复习到第 2 层时请把这些位置也背住。

## 二、你最好先具备的前置知识

这套笔记假设你已经会（或边看边补）：

- **C++ 基础**：RAII、`std::shared_mutex`、`std::mutex`、protobuf 基本用法、回调/闭包。
- **计算机网络**：HTTP 长轮询、gRPC(HTTP/2)、端口与进程模型常识。
- **操作系统**：fsync 与落盘、进程/线程、`kill -9`/`SIGSTOP` 语义。
- **分布式入门直觉**：CAP、为什么多副本会不一致（不需要精通，第 01 章会带）。

> 真薄弱的部分不用慌：`01`/`02` 两章就是按"考点驱动、必考的讲透"来写的，够用为止；想更深入去翻文末延伸文档。

## 四、全文统一约定（重要）

1. **路径**：`src/xxx` 均相对项目根 `configraft/`。代码引用形如 `raft_node.cpp:166` 表示 `src/raft/raft_node.cpp` 第 166 行附近。复习请以**真实源码为准**——面试前如行号有漂移，用你本地的源码为准，本笔记行号是撰写时的快照。
2. **数字口径**：性能数字一律以 **`../性能压测报告.md`（2026-08 阿里云 8 核实测、审查加固后）** 为准，不混用 m7 的 4 核 VM 旧数据。
3. **术语**：
   - `revision` = 全局逻辑时钟（每写 +1，跨 key 单调），Watch/CAS/MVCC 的共同锚点。
   - `version` = 单个 key 的修改序号（从 1 起），配置发布/回滚看它。
   - `commit_index` / `applied_index` = braft 的已提交 / 已应用日志下标。
4. **代码引用只为定位讲解，本笔记不含大段源码**：贴的都是"伪代码 + 关键判断"，防止你背代码；真要看实现，按引用去翻。
