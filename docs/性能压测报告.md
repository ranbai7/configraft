# Configraft 性能压测报告

> 2026-08-20 云服务器实测。本报告数据用于 README「性能与验证」章节及面试讲解。
> 复现命令：`bash scripts/benchmark.sh --all --dur 10`（自动跑 fsync 开关 × 单机/集群 × gRPC/HTTP 读写矩阵）。

## 1. 测试环境

| 项 | 值 |
|---|---|
| 机器 | 阿里云按量云主机（单台） |
| CPU | 8 vCPU |
| 内存 | 14G |
| 磁盘 | NVMe SSD |
| 系统 | Ubuntu 22.04（内核 5.15） |
| 工具 | ghz 4.0（gRPC）、wrk 4.1（HTTP） |
| 压测方式 | 客户端与 server 同机（127.0.0.1），每项 10s |
| 集群形态 | 单机（1 进程）与 3 节点集群（3 进程跑同一台云主机） |

> 说明：3 节点集群为**同一台云主机上运行 3 个 server 进程**，进程间通过本地环回通信；
> 真实多机部署下网络 RTT 略高，但写吞吐基本受 CPU/磁盘主导，本数据具代表性。

## 3. 汇总对比表

| 场景（每项 10s） | 单机 | 3 节点集群 · 默认持久化 | 3 节点集群 · 关 fsync |
|---|---|---|---|
| gRPC 写 Put · 8 并发 | 28.6k QPS / P99 0.45ms | 1.8k / 11.3ms | 15.5k / 1.5ms |
| gRPC 写 Put · 32 并发 | 36.5k / 2.1ms | 5.6k / 11.4ms | 24.2k / 3.4ms |
| gRPC 写 Put · 64 并发 | 39.2k / 3.3ms | 10.0k / 11.7ms | 27.4k / 4.9ms |
| gRPC 读 Get · 64 并发 | 46.5k / 2.7ms | 44.1k / 2.7ms | 44.0k / 2.8ms |
| HTTP 读 GET · 100 连接 | 290k / 0.47ms | 269k / 0.54ms | 260k / 0.62ms |
| HTTP 写 POST · 100 连接 | 101k / 1.4ms | 17k / 11.9ms | 73k / 3.3ms |

## 4. 结论

1. **读远高于写**：HTTP GET 约 27 万 QPS，写路径 1.8k–27k QPS —— 符合配置中心"读多写少"的业务形态，读路径对任何配置拉取场景都绰绰有余。
2. **写路径最大开销是 Raft 日志 fsync**：集群 8 并发时，默认持久化 1.8k vs 关 fsync 15.5k，差距约 **8.5 倍**。这是"强一致 + 崩溃不丢已提交日志"的固有代价（`--raft_sync=false` 仅压测/演示用）。
3. **单机 vs 集群写差距体现 Raft 多数派复制开销**：无复制单机 39k（c64），集群默认持久化 10k、关 fsync 27k。
4. **读路径不受 fsync 影响**（leader lease 本地读，无写盘），三个配置基本一致。
5. **并发扩展性**：集群写 c8→c64 从 1.8k 涨到 10k（默认），关 fsync 从 15.5k 涨到 27k（接近 8 核 CPU 上限，收益递减）——写路径在 fsync 排队下扩展性受限，印证 fsync 为瓶颈。

## 5. 复现方法

```bash
# 云主机或任意已编译环境
bash scripts/benchmark.sh --all --dur 10
```

`--all` 自动跑 fsync 开/关 × 单机/集群 四个配置的完整读写矩阵；对当前集群单独压测用 `bash scripts/benchmark.sh --dur 10`。
